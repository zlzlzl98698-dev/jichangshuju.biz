  - q: 什么场景非开 TUN 模式不可，不能只靠系统代理？
    a: Windows/macOS 的“系统代理”仅仅是写入系统环境里的一个建议地址，只对 Chrome/Edge 浏览器这类主动去读取它的程序生效；而大量命令行工具（Git、npm、pip、curl、Docker）、现代 AI 桌面客户端、部分 IDE 插件（VS Code/Cursor 某些底层的二进制组件）、Windows UWP 应用和 PC 端游启动器根本不会读取系统代理设置。开启 TUN 模式会在系统最底层建一张虚拟网卡，把所有无视系统代理的流量强行收归代理核心按规则接管，一劳永逸解决“浏览器能翻、终端报错超时”的问题。
  - q: 开启 TUN 后，公司办公 VPN 或部分游戏反作弊闪退正常吗？
    a: 因为同一时间操作系统底层通常只允许一张“主默认出口虚拟网卡”控制路由优先级。如果你开着机场客户端的 TUN 虚拟网卡，又同时启动了公司远程办公 VPN、校园网客户端或极少数严苛反作弊网游，两套虚拟网卡驱动会互相抢夺并覆写系统路由表，导致所有网全断或程序报异常退出。解决方法是：**开公司 VPN 或打高对抗反作弊网游时，务必暂时关掉代理的 TUN 模式（只留纯网页系统代理即可）**。
  - q: "`Fake-IP` 和 `Redir-Host` 两个 DNS 模式普通用户怎么选？"
    a: 简单对比：`Fake-IP` 遇到任何域名查询时会立刻先编造一个高速虚拟假 IP（如 `198.18.x.x`）秒级扔给浏览器，从而省去等待远端真实 DNS 解析的来回延迟，把实际解析动作打包丢给远程节点执行，速度极快且彻底根治 DNS 泄漏，适合 90% 日常网页和流媒体场景；`Redir-Host` 则老老实实向 DNS 服务器查询真实目标 IP 返回给本地，适合对真实 IP 有校验要求的极客/内网抓包调试或局部开发软件环境。
  - q: "开着 Fake-IP 时，在终端里 ping 海外域名返回 `198.18.x.x` 是被劫持了吗？"
    a: 不是中毒，这正是 `Fake-IP` 在正常工作！`198.18.0.0/15` 是国际保留用于基准测试和虚拟映射的网段，Clash/Mihomo 内核用它来占坑接管域名连接（如果你希望国内常用域名如 baidu.com 或公司局域网地址不被映射成 Fake-IP，只需要把它们加进客户端配置文件的 `fake-ip-filter` 跳过列表里即可）。
  - q: Chrome / Edge 浏览器开着代理却仿佛不生效、或者国内国外乱跳是怎么回事？
    a: 因为建立虚拟网卡需要系统管理员级底层内核驱动权限。在 Clash Verge Rev 中点击左侧“设置 → 服务模式 (Service Mode)”右侧的盾牌或齿轮安装按钮，按提示授权管理员密码安装后台系统服务，重启一次客户端之后即可自由顺畅地开启或关闭 TUN 模式。

# TUN 模式与 DNS 配置详解（Fake-IP vs Redir-Host）

**用一句极简的话分清电脑端两种核心开关：“系统代理（System Proxy）”管的是浏览器与配合读取设置的软件，而“TUN 虚拟网卡模式”则是操作系统 IP 层的全自动底网接管——专门负责治好各种命令行终端（Git/npm/curl）、AI 桌面应用、WSL/Docker 与微软商店 UWP“浏览器能上、软件本身却死活连超时”的疑难杂症。**

掌握了 **TUN 虚拟网卡接管权限**，再搞懂它背后决定域名分流生死的 **`Fake-IP` vs `Redir-Host` 双 DNS 机制**，你就真正跨入了电脑代理配置的专业门槛。

---

## 一、系统代理 vs TUN 虚拟网卡模式：什么时候需要开 TUN？

| 对比维度 | 系统代理模式（System Proxy） | TUN 虚拟网卡模式（TUN Mode） |
|---|---|---|
| **工作层级与技术原理** | 修改系统 HTTP/SOCKS 本地端口环境变量（通常 `127.0.0.1:7897`） | 在内核层创建虚拟网卡（如 `Meta` / `utun`）接管 **全量 TCP + UDP 数据包** |
| **需要管理员/系统权限吗** | **不需要**（普通用户即开即用） | **需要**（Windows 需安装 Service 服务或管理员运行；macOS 需输入开机密码授权 Helper） |
| **能管到终端 / Git / 游戏 UDP 吗** | **管不到**（绝大多数命令行和 UDP 流量直接忽略系统代理） | **全盘接管**（终端 CLI、Python 脚本、AI 客户端、UWP、UDP 全按规则自动分流） |
| **与公司 VPN / 网游反作弊兼容** | **互不干扰**（极其安全安静） | **容易冲突抢占路由表**（使用企业办公 VPN 或打竞技游戏前请关闭 TUN） |
| **日常推荐开启姿势** | 平时仅刷网页看剧写文档：**只开它就够了** | 开发者开终端拉依赖、需运行桌面 AI 或抓全盘流量：**再顺手打开它** |

## 二、DNS 配置核心对比：`Fake-IP` vs `Redir-Host` 怎么选？

代理软件想要实现“`Rule` 模式国内直连、国外走节点”，首先必须截获你访问的域名并做正确的 DNS 解析。一旦 DNS 没接管好，就会产生所谓的 **“DNS 泄漏”或“本地先被污染成错误 IP 导致全部连超时”**。在 Mihomo（Clash.Meta）与 OpenClash 等现代内核中，DNS 有两种主要工作流：

### 1. `Fake-IP` 模式（现代客户端与软路由默认优选）
- **核心机制**：当你的浏览器请求 `www.google.com` 时，本地客户端**根本不等远程慢悠悠解析真实 IP**，而是立刻瞬间编造返回一个内部假 IP（默认落在 **`198.18.0.1/16`** 段）塞给浏览器发起连接；紧接着在底层拦截到指向假 IP 的数据包时，再连同域名本身打包发给海外节点，让海外服务器直接在当地解析并连接真实目标！
- **四大突出优点**：
  - **域名响应延迟极度逼近 0ms**（省去了先等 DNS 往返一趟的时间）；
  - **彻底杜绝 DNS 污染与本地 DNS 泄漏**（海外域名根本不在本地进行真实解析）；
  - 当你从 Wi-Fi 切换到 4G、或者只靠 IP 连接时分流规则命中率极高（客户端直接把域名还原本质）；
  - 内存资源占用与路由表维护比传统方案更省。
- **唯一微小缺点与解决（`fake-ip-filter`）**：因为返回了 `198.18.x.x` 假地址，极少数依赖校验域名真实 IP 的国内网银组件、游戏检测、NAS 局域网登录（如 `*.local`）或某些 Windows 网络状态图标（NCSI）会误以为没网或发懵——解决方法只需在配置文件的 `dns.fake-ip-filter` 清单里把常见局域网后缀、NTP 对时服务器与特定国内组件加进“跳过名单”，让它们依然获得真实 IP。

### 2. `Redir-Host` 模式（传统实地址解析模式）
- **核心机制**：老老实实向设定好的国内外分组 DNS（例如国内走 `223.5.5.5` 阿里 DoH、国外走 `8.8.8.8` 或代理通道解析）询问域名对应的真实世界 IP 地址，拿到真实 IP 后再判断发给代理还是直连。
- **适用场景**：适合部分专业开发测试环境、必须在本地终端明确抓包看到真实目标公网 IP 地址的用户，或遇到了某些与 `198.18.x.x` 极度八字不合的老旧企业客户端。
- **需要注意的缺点**：如果在国内 DNS 未做好严格 `geosite` 分流过滤，很容易出现并发解析卡顿，或是把本该走海外解析的域发送给国内本地运营商 DNS 导致污染出错。

## 三、开启 TUN + DNS 必过的三个系统坑位

1. **Windows 必须安装 Service Mode（服务模式）**
   在 [Clash Verge Rev](/clients/clash-verge) 中如果找不到或点不开 TUN，请前往“设置”点击安装服务模式再重启客户端；用 [v2rayN](/clients/v2rayn) 则必须每次右键图标选择“以管理员身份运行”。
2. **注意关闭浏览器里“自带的加密 DNS（DoH）”**
   Chrome、Edge 与 Firefox 现代版本经常默认开启“使用安全 DNS（DNS-over-HTTPS）”。如果在浏览器的设置里打开了这个功能，浏览器请求 DNS 时就会绕开 Clash 截获通道，直接跑向公共加密 DNS，**结果就是分流规则大面积失灵、国内网站慢或者假死！** 建议在电脑浏览器设置里将“使用安全 DNS”关闭，交由代理客户端统一托管。
3. **冲突自查：遇到开 TUN 反而不通网怎么办？**
   - 检查本机是不是同时开着另一款加速器（如 UU/雷神）、公司办公 VPN（AnyConnect/EasyConnect/Pulse）或者虚拟机（Docker/VMware 的桥接冲突网卡）。
   - 如果同时开着它们，请第一时间关掉 TUN 模式做对比测试，详见专项排错指南：[Clash TUN 模式与企业 VPN/游戏冲突解决](/diagnostics/clash-tun-conflict)。

## 四、信息边界与诚实披露

- **各机场配置模板默认差异**：并非所有机场官方下发的订阅链接里都已经写好完善的 `fake-ip-filter` 与 `dns:` 区块；有些精简模板仅含基础节点与代理组，需要靠客户端自身默认的全局 DNS 规则兜底（在 Clash Verge Rev 中通常默认内置了稳妥的混合 DNS 兜底设定，切勿随意盲目套用网络未知脚本全盘覆写 DNS 块，以免把客户端弄瘫）。
- **DNS 速度异常排查入口**：如果调整后依然出现解析极其缓慢或打开某些本地网站卡在“正在解析主机”，请直接转到 [DNS 与网速异常故障排查](/diagnostics/dns-speed)。

## 五、常见问题（FAQ）

<details class="ad-faq-details" open>
<summary>什么场景非开 TUN 模式不可，不能只靠系统代理？</summary>

浏览器、Telegram 等能识别系统代理；但命令行终端（Git、npm、pip、curl、Docker）、微软商店 UWP 应用、桌面端 AI 工具底层脚本与部分外服启动器默认无视系统代理，此时必须打开 TUN 虚拟网卡接管全系统 IP 层流量。

</details>

<details class="ad-faq-details">
<summary>开启 TUN 后，公司办公 VPN 或部分游戏反作弊闪退正常吗？</summary>

属于正常的底层路由争夺冲突。同一时间操作系统通常只宜由一套底层网络隧道接管默认路由，因此打开公司内网 VPN 或启动大型竞技游戏时，请先关闭代理软件里的 TUN 开关。

</details>

<details class="ad-faq-details">
<summary>`Fake-IP` 和 `Redir-Host` 两个 DNS 模式普通用户怎么选？</summary>

90% 的常规用户优先维持现代客户端推荐的 **`Fake-IP`**（响应近乎零延迟且彻底防污染）；只有遇到特定开发抓包或老软件校验真实 IP 报错时，才临时改切 `Redir-Host`。

</details>

<details class="ad-faq-details">
<summary>开着 Fake-IP 时，在终端里 ping 海外域名返回 `198.18.x.x` 是被劫持了吗？</summary>

完全不是劫持或中毒，`198.18.0.0/15` 正是 Clash/Mihomo 内核用来做高速虚假占位映射的国际保留测试地址段，说明您的 Fake-IP DNS 接管机制正在正常运行。

</details>

<details class="ad-faq-details">
<summary>Chrome / Edge 浏览器开着代理却仿佛不生效、或者国内国外乱跳是怎么回事？</summary>

重点去浏览器的“隐私与安全”设置检查是否开启了浏览器自带的“使用安全 DNS（DoH）”。浏览器内置 DoH 会跳过本地 Clash 的 DNS 监听直接向外发解析包，关闭它交回系统与代理客户端托管即可恢复正常分流。

</details>
